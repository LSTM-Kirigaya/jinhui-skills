# 评审报告模板

## 1. 结论摘要

- 作品类型：
- 用户确认的成熟参照物：
- 证据基线总分：
- 用户校准总分：
- 总体置信度：
- 一句话结论：

## 2. 评审范围

| 对象 | 仓库/材料 | Commit/版本 | Demo | 评审日期 |
|---|---|---|---|---|

列出未获得或未验证的材料。

## 3. 类型与参照物确认

说明作品为何属于软件、框架或混合型；记录用户确认结果。

对每个参照物说明：

- 类型与可比性；
- 成熟度的真实证据；
- 已知短板；
- 与用户品味的匹配；
- 用户为何保留或拒绝。

## 4. 声明核验

使用证据台账：

| ID | 核心声明 | 源码证据 | 测试/运行/作品证据 | 判定 | 置信度 |
|---|---|---|---|---|---|

优先展示最影响评分的支持证据和反证。

## 5. 与成熟参照物对比

| 能力 | 待评作品 | 参照物 | 差距及意义 | 证据 ID |
|---|---|---|---|---|

只比较用户确认的参照物，不临时加入新竞品。

## 6. 证据基线评分

| 维度 | 权重 | 分数 | 加权分 | 证据 ID | 置信度 |
|---|---:|---:|---:|---|---|
| 场景价值与行业可复制性 | 25% | | | | |
| Agent 协同与自主闭环 | 25% | | | | |
| Skill 工程体系与生态复用 | 25% | | | | |
| 工程落地、运行验证与安全可审计 | 20% | | | | |
| 开放与开源贡献 | 5% | | | | |

每项附：支持证据、反证、未验证内容、适用上限、为什么是该分数。

## 7. 用户校准记录

| 项目 | 证据基线 | 用户调整 | 最终值 | 调整理由 |
|---|---:|---:|---:|---|

若用户未校准，写“保持证据基线”。

## 8. 可粘贴到评审表的内容

分别提供五项简洁评分理由和一段总体评语。事实性表达引用证据 ID，正式粘贴版可移除 ID。

## 9. 风险与改进建议

- P0：影响真实性、安全或基本可运行性的事项；
- P1：影响成熟度与复用性的事项；
- P2：体验、生态和长期演进事项。

## 10. 提高置信度所需材料

列出进一步确认结论所需的源码、账号、部署文档、Trace、测试报告或演示步骤。
