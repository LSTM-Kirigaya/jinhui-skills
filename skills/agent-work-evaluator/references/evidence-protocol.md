# 证据协议

## 1. 证据优先级

从强到弱：

1. 固定版本的源码、自动化测试和可复现运行结果；
2. 与 commit 对应的构建产物、发布包和端到端演示；
3. CI、评测集、Benchmark、Tracing、审计轨迹和真实案例；
4. 官方技术文档、API 文档和架构说明；
5. 在线 Demo、视频和截图；
6. README、PPT、市场文案和口头说明。

低等级声明不能推翻高等级反证。知名度、Star、融资和作者背景不是功能实现证据。

## 2. 版本固定

每个对象记录：

```text
对象：
仓库/产品 URL：
类型：软件 / 框架 / 混合
分支：
Commit / 版本：
评审日期：
Demo / 附件：
允许执行范围：
```

临时克隆应放在工作区的临时目录，结束后用可恢复方式清理。不要修改被评仓库。

## 3. 声明核验矩阵

为每个关键声明分配证据 ID：

| ID | 声明 | 实现位置 | 测试证据 | 运行/作品证据 | 反证或限制 | 判定 | 置信度 |
|---|---|---|---|---|---|---|---|
| E-01 | 支持多 Agent 并行 | `src/...:line` | `tests/...` | Trace/日志 | 仅共享上下文 | 部分实现 | 中 |

判定只使用：

- **已实现**：源码路径清楚，且测试或运行证据支持；
- **部分实现**：有可执行骨架，但关键语义缺失；
- **仅集成**：调用外部能力，本仓库未实现核心；
- **仅声明**：只有文档或 UI 文案；
- **与声明矛盾**：源码或运行结果直接反驳；
- **未验证**：材料或权限不足。

置信度：

- **高**：源码、测试和运行相互印证；
- **中**：有源码与部分运行/测试证据；
- **低**：主要依赖文档、Demo 或间接推断。

## 4. 源码核验清单

### Agent Loop

- 模型调用入口；
- 工具调用解析与执行；
- 工具结果如何回到模型；
- 停止条件、迭代上限和错误路径。

### 多 Agent

- 子 Agent 的创建和销毁；
- 独立上下文与状态隔离；
- 委派、并行、取消、超时；
- 结果汇聚和错误传播。

### Skill

- 定义格式和元数据；
- 发现、加载和卸载；
- 依赖与权限；
- 版本、测试、组合与分发。

### 上下文与持久化

- 会话状态、Checkpoint、恢复；
- Memory、压缩、Offload；
- 并发一致性和损坏恢复。

### 安全与审计

- 输入验证、权限、沙箱、凭证；
- 敏感动作的批准与中断；
- 审计是否记录真实输入、结果和失败；
- 是否存在固定成功、吞异常或失败继续完成。

### 工程质量

- 干净构建与启动；
- 单元、集成、端到端测试；
- CI、依赖锁定、发布、升级；
- 重复代码、生成物、二进制和缺失模块。

## 5. 运行验证规则

- 只做与用户授权和风险相称的最小验证；
- 不自动向外部系统提交数据、创建资源或触发付费调用；
- 记录执行命令、环境、退出码和关键输出；
- 测试失败不能被“页面能打开”覆盖；
- 在线 Demo 与源码无法对应时，标注“演示存在，源码归因未验证”；
- 使用 Mock 时明确标注，不能作为真实闭环证据。

## 6. 每项评分的最低证据结构

```text
分数：x/10
支持证据：E-01、E-03
反证：E-05
未验证：部署后端源码
应用的分数上限：无 / 具体规则
置信度：高 / 中 / 低
判断：为什么这些证据对应这个分数，而不是相邻分数
```
